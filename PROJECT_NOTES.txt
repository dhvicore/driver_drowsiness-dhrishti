DRISHTI: REAL-TIME DRIVER DROWSINESS AND DISTRACTION DETECTION
Technical Summary

1. SYSTEM OVERVIEW

Drishti is a real-time driver monitoring system that detects drowsiness and distraction using a single standard webcam. Each frame (1280 x 720 pixels) is processed by the MediaPipe Face Landmarker, which locates 478 facial landmarks. Geometric features are computed from selected landmarks, analysed over time, and combined into risk scores that classify the driver as ALERT, FATIGUED, DROWSY, DISTRACTED or CRITICAL. The system runs at approximately 30 frames per second on a consumer laptop (Apple MacBook Air).

Processing pipeline: Camera -> Facial landmark detection -> Feature extraction -> Temporal analysis -> Risk scoring -> Driver status.

Implementation: Python, OpenCV, MediaPipe, Ultralytics YOLO11, TensorFlow/Keras, Flask (backend) and Next.js (frontend).


2. FEATURE EXTRACTION

Five primary features are extracted from each frame:

  Feature                     Description                     Source
  Eye Aspect Ratio (EAR)      Degree of eye opening           6 landmarks per eye
  Mouth Aspect Ratio (MAR)    Degree of mouth opening         4 mouth landmarks
  Pitch                       Vertical head rotation          6 landmarks + 3D face model
  Yaw                         Horizontal head rotation        6 landmarks + 3D face model
  Phone detection             Mobile phone in view            YOLO11 (COCO class 67)

The eye aspect ratio is defined as:

  EAR = (||p2 - p6|| + ||p3 - p5||) / (2 * ||p1 - p4||)

where p1 and p4 are the eye corners and (p2, p6) and (p3, p5) are vertical eyelid landmark pairs. The value is averaged across both eyes.

The mouth aspect ratio is defined as the vertical distance between the inner upper and lower lip divided by the horizontal distance between the mouth corners.

EAR, MAR, pitch and yaw are each smoothed using a moving average over 7 frames to reduce noise.

From these, the following temporal features are derived: blink count, long eye closures, PERCLOS (the percentage of time the eyes are closed within a 30-second window), and confirmed yawn events.


3. DROWSINESS DETECTION

3.1 Thresholds

  Parameter                         Value
  Eye considered closed             EAR < 0.23
  Eye considered reopened           EAR > 0.27
  Blink duration                    0.08 - 0.65 s
  Long closure (microsleep)         >= 0.8 s
  Yawn onset                        MAR > 0.42
  Yawn end                          MAR < 0.28
  Minimum yawn duration             0.65 s
  PERCLOS window                    30 s
  Yawn memory window                45 s
  Long-closure memory window        30 s

Separate closing and reopening thresholds (hysteresis) prevent rapid state switching when EAR is near the boundary. The minimum yawn duration distinguishes yawning from speech.

3.2 Evidence Score

A drowsiness evidence score between 0 and 100 is computed for each frame by summing weighted indicators:

  Indicator                       Points
  Current eye closure             >= 0.8 s: 20;  >= 1.5 s: 45;  >= 2 s: 65;  >= 3 s: 85
  PERCLOS                         >= 20%: 10;  >= 30%: 18;  >= 40%: 25;  >= 50%: 30
  Recent yawns (45 s)             1: 10;  2: 20;  3 or more: 30;  active yawn: +5
  Recent long closures (30 s)     1: 8;  2-3: 18;  4 or more: 25
  Combined indicators             +10 when eye closure >= 0.8 s coincides with
                                  >= 2 recent yawns or PERCLOS >= 35%

3.3 Score Smoothing

The displayed drowsiness score follows the evidence score asymmetrically: it closes 20% of the difference per frame when rising and 8% when falling. This allows rapid response to danger while preventing premature return to the alert state.

3.4 Classification

  Status      Condition
  CRITICAL    Eye closure >= 3 s, or >= 2 s with >= 2 recent yawns
  DROWSY      Eye closure >= 1.5 s; or PERCLOS >= 45% with >= 2 long closures;
              or score >= 55 with PERCLOS >= 35% or closure >= 0.8 s
  FATIGUED    >= 2 recent yawns, or score >= 30
  ALERT       None of the above


4. DISTRACTION DETECTION

4.1 Head Pose Estimation

Head orientation is estimated with the Perspective-n-Point algorithm (OpenCV solvePnP), matching six facial landmarks (nose tip, chin, outer eye corners and mouth corners) to a generic 3D face model. The focal length is approximated by the frame width.

  Direction   Threshold          Distraction after
  Left        yaw < -25 deg      1.5 s
  Right       yaw > 20 deg       1.5 s
  Up          pitch < -15 deg    1.5 s
  Down        pitch > 20 deg     1.2 s

4.2 Phone Detection

Mobile phones are detected with YOLO11 (small variant) using the COCO "cell phone" class. To detect small or partially visible phones, the frame is analysed both as a whole (confidence >= 0.20) and as five overlapping tiles (confidence >= 0.16). A detection is considered stable when present in at least 3 of the last 10 checks, and phone use is declared after 1.0 s of continuous detection. Because object detection is computationally expensive, it is executed every 8 frames.

4.3 Distraction Score

  Indicator                       Points
  Head left / right / up          >= 0.5 s: 15;  >= 1 s: 35;  >= 1.5 s: 55;  >= 3 s: 75
  Head down                       >= 0.4 s: 20;  >= 0.8 s: 40;  >= 1.2 s: 60;  >= 2.5 s: 80
  Phone detected                  +15
  Phone in use                    +35
  Phone in use with head down     +40

The score is capped at 100.

4.4 Final Driver Status

The final status combines both analyses, evaluated in order of priority: CRITICAL (critical drowsiness, or drowsiness with a distraction score >= 60); DROWSY; DISTRACTED (distraction score >= 60, or phone use with the head turned down); FATIGUED; DISTRACTED (head turned away or phone in use); and ALERT.


5. DEEP-LEARNING YAWN CLASSIFIER

As an alternative to the geometric MAR method, a convolutional neural network was trained to classify mouth images as "yawn" or "no yawn".

  Setting              Value
  Architecture         MobileNetV2 (ImageNet weights, frozen) + Global Average
                       Pooling + Dropout (0.3) + Dense (1, sigmoid)
  Input size           224 x 224 x 3
  Batch size           32
  Optimiser            Adam, learning rate 0.001
  Loss                 Binary cross-entropy
  Training             Up to 15 epochs with early stopping
  Augmentation         Horizontal flip, rotation, zoom, contrast
  Dataset              5,119 images: 3,582 training, 767 validation, 770 test
                       (70 / 15 / 15 split)

Test set results (770 images):

  Metric               Value
  Accuracy             97.92%
  Precision (yawn)     98.40%
  Recall (yawn)        97.37%
  F1-score             0.98

  Confusion matrix     Predicted normal    Predicted yawn
  Actual normal        384                 6
  Actual yawn          10                  370

Although the classifier achieved high accuracy, the geometric MAR approach was adopted for the real-time system because it requires no image cropping and has lower computational cost, which suits continuous real-time operation.


6. SYSTEM IMPLEMENTATION

The detection pipeline runs in a Python Flask server that streams annotated video frames (MJPEG, approximately 30 fps) and publishes the computed metrics as JSON. A Next.js web dashboard displays the live video, driver status, risk scores and an event log, refreshing every 250 ms.


7. LIMITATIONS

The system requires the driver's face to be visible and adequately lit; sunglasses prevent reliable EAR measurement. Thresholds are fixed rather than calibrated per driver. Downward head movement can reduce apparent eye opening and be mistaken for eye closure. Phone detection requires the phone to be within the camera's view.
